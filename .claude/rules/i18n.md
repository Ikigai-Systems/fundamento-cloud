# User-facing text: use Rails i18n, not hand-written logic

Text that depends on a count goes through Rails i18n with `zero` / `one` / `other` keys and a
`count:` argument, not through `pluralize`, conditionals or string building in a controller or
view:

```yaml
en:
  documents:
    archive:
      notice:
        zero: "Document has been archived."
        one: "Document and its %{count} descendant have been archived."
        other: "Document and its %{count} descendants have been archived."
```

```ruby
t("documents.archive.notice", count: descendants)
```

i18n picks the form, so the singular case can't be forgotten, and the grammar of each form is
written down where it can be read: a hand-coded version of the message above once said "1
descendant has".

Most existing UI strings are still hardcoded English. Don't migrate them unasked; put new text
that needs plural forms in `config/locales/en.yml`. English needs only `one` / `other`; other
locales would need the `rails-i18n` gem for their plural rules.

When a framework already has a mechanism for the thing (plurals, dates, number formats), use it
rather than coding the behaviour by hand.

Say "descendants" for everything beneath a document (children, grandchildren, and deeper), not
"sub-documents".
